# ISO 9660 optical disc images

`src/formats/iso9660.rs` and its submodules parse ISO 9660 (ECMA-119)
filesystem images into the shared container model
([compressed streams and the container model](compressed-streams.md)). The
volume descriptor set is read from sector 16, the directory hierarchy is
walked with names from Rock Ridge, Joliet or the ISO 9660 identifiers, El
Torito boot images become children, and regular files in a recognized
format become members labeled by their path. The format names no processor:
only an El Torito platform ID names one, for its boot image.

## Implemented layouts

| JSON format ID | Layout | Architecture evidence | Primary source |
| --- | --- | --- | --- |
| `iso9660` | `CD001` at 0x8001; volume descriptor set from sector 16 to its terminator (primary, supplementary, enhanced, partition, boot record); primary volume descriptor with both-byte-order fields that agree, logical block size 512, 1024 or 2048 and a valid root record; directory records (multi-extent files, extended attribute records); type L and type M path tables cross-checked | None for the volume; members are classified from their own bytes | [ECMA-119 4th edition (2019)](https://ecma-international.org/wp-content/uploads/ECMA-119_4th_edition_june_2019.pdf), 6.1-6.9, 7.2-7.6, 8.1-8.6, 9.1-9.4, 10 |
| Joliet (names) | Supplementary volume descriptor with escape sequences `%/@`, `%/C` or `%/E` (UCS-2 levels 1-3); UCS-2 big-endian identifiers; its own hierarchy | None | ECMA-119 Annex C (the Joliet Specification of 1995-05-22) |
| Rock Ridge (names) | SUSP `SP` (check bytes `BE EF`, `LEN_SKP`) at the root's `.` record (or after 14 bytes of CD-ROM XA information); `ER` with `IEEE_P1282` or `RRIP_1991A`, or an RRIP 1.09 `RR` entry; `CE` continuation areas; `NM`, `PX`, `CL`, `RE`, `SF`, and Linux `ZF` | None | IEEE P1281 SUSP 1.12 (4, 5.1-5.5) and IEEE P1282 RRIP 1.12 (4.1.1, 4.1.4, 4.1.5, 4.1.7, 4.3), 1994-07-08 drafts; libarchive v3.7.4 `archive_write_set_format_iso9660.c` for `RRIP_1991A` |
| El Torito (children) | Boot record (`EL TORITO SPECIFICATION`, catalog sector at 0x47); validation entry checksum and key bytes verified; default entry; section headers (0x90/0x91) with their entries and extensions (0x44) | Platform ID 0 with no emulation: x86 real mode (16-bit, little-endian); platform ID 1 with no emulation: PowerPC, byte order from the code; all other platforms and emulations: none | El Torito Bootable CD-ROM Format Specification 1.0 (Phoenix/IBM, 1995-01-25), figures 2-7, 4.1, 4.3; libisofs `release-1.5.6` `doc/boot_sectors.txt` for platform 0xEF (UEFI 2.4 12.3.2.1) |
| UDF bridge (noted) | ECMA-167 volume structure descriptors after the terminator: `BEA01`, `NSR02`, `NSR03`, `BOOT2`, `CDW02`, `TEA01` | None | [ECMA-167 3rd edition (1997)](https://ecma-international.org/wp-content/uploads/ECMA-167_3rd_edition_june_1997.pdf), 2/8.3, 2/9.1-9.3, 3/9.1 |

Field-level notes with offsets, sizes and sources are kept with the
implementation: `descriptors.rs` (Tables 4 and 6), `directory.rs` (Table 8),
`susp.rs` and `eltorito.rs` list the layouts they read.

### Name source

The hierarchy that supplies the names is chosen as Linux v6.11
`isofs_fill_super` and libarchive `choose_volume` choose it:

1. Rock Ridge, when the primary root shows it: the primary hierarchy, names
   from `NM` entries; an entry without `NM` keeps its ISO 9660 identifier
   (hdiutil writes Rock Ridge without `NM`), and the count is noted.
2. Otherwise Joliet, when a valid Joliet descriptor exists and its root
   lies in the volume.
3. Otherwise the primary hierarchy with ISO 9660 identifiers, version
   numbers (`;1`) and an empty extension's trailing `.` removed.

Rock Ridge relocation is followed: a record with `CL` is walked as the
directory it names (its size from the moved directory's `.` record), and a
directory with `RE` is skipped where it was moved to (`rr_moved`).

### El Torito boot images

| Platform ID | Emulation | Child | Size |
| --- | --- | --- | --- |
| 0 (80x86) | none | Raw code for the code model, target x86 16-bit little-endian (the BIOS loads it at the load segment and jumps to it, 4.3) | The file whose data starts at the load RBA, else the sector count x 512 B |
| 0xEF (EFI) | none | Classified from its own bytes (an EFI system partition, usually FAT) | The matching file, else sector count x 512 B; a sector count below 2 means to the end of the volume (EDK2 `ElTorito.c`) |
| 1 (PowerPC) | none | Classified from its own bytes, target PowerPC 32-bit with the byte order from the code | As for 80x86 |
| 2 (Mac) and others | none | Classified from its own bytes; no ISA named | As for 80x86 |
| any | 1.2, 1.44, 2.88 MB floppy | Disk image, classified from its own bytes | 1,228,800, 1,474,560 or 2,949,120 B (4.1 geometry) |
| any | hard disk | Disk image, classified from its own bytes | The matching file, else the end of the first MBR partition (4.1) |

A boot image whose data a regular file holds is labeled by the catalog
entry and the note names the file; the file is not listed again as a
member. Entries marked not bootable (0x00) are counted. Boot images follow
the files, so a recognized file supplies the primary ISA and a boot image
does only when no file is recognized: authoring tools put the same x86
boot loaders on discs for any machine.

## Wire units and byte order

- Logical sectors are 2048 bytes; the descriptor set starts at 0x8000.
  Extents count logical blocks of the volume's block size; data starts after
  any extended attribute record blocks.
- Descriptor and directory numbers are recorded in both byte orders (7.2.3,
  7.3.3). In the primary volume descriptor both halves must agree. In
  directory records the little-endian half is used, as Linux (`isonum_733`)
  and libarchive read it, and disagreements are counted in a note.
- Type L path tables are little-endian, type M big-endian.
- Joliet text is UCS-2 big-endian. Rock Ridge names are bytes, shown as
  UTF-8 with replacement.
- El Torito fields are little-endian; load RBAs count 2048-byte sectors and
  sector counts 512-byte virtual sectors.
- Offsets in notes and metadata are file bytes.

## Validation and resource bounds

- Detection: the full sector at 0x8000 must be present; descriptors are
  read from sector 16 until the first primary volume descriptor (at most 64
  sectors).
- Parse errors: no terminator within 64 sectors or a sector without `CD001`
  before it; trailing bytes after the volume that are not padding, unless
  the system area holds an MBR with partitions or a GPT header (hybrid
  images may append partitions); a root directory outside the volume; a
  volume larger than the file whose root directory lies past the end of
  the file (see "Truncated volumes").
- Damage below the root (an invalid record, a directory or file outside the
  volume, interrupted multi-extent files, bad Rock Ridge entries, bad names)
  is noted, at most 16 problems listed and the rest counted.
- Directories are visited once by file offset, so cycles and repeated
  directories cannot loop. The walk enters at most 65,536 directories, at
  most 64 levels deep, with paths up to 4096 B, and reads at most twice the
  volume size (for a truncated volume, twice the bytes present) in
  directory data.
- At most 32 continuation areas per system use area (Linux
  `RR_MAX_CE_ENTRIES`), each inside the volume; Rock Ridge names longer than
  255 B fall back to the ISO 9660 identifier.
- A file has at most 1024 sections. Members are recognized from their first
  4 KiB; at most 4096 members, 64 MiB each and 256 MiB probed and listed in
  total (`MAX_COMPONENTS`, `MAX_PAYLOAD`, `MAX_EXTRACTED`), with what was
  left out noted. Contiguous members are borrowed; multi-extent files with
  gaps are reassembled (transform `ISO 9660 file sections`).
- The boot catalog is read up to 64 KiB (2048 entries); boot images larger
  than 64 MiB are not listed.

## Truncated volumes

A volume whose volume space size times its logical block size (ECMA-119
8.4.8, 8.4.12) exceeds the file is read as a truncated volume. Containers
decode at most 64 MiB of a component (`MAX_PAYLOAD`), so a larger image in
a DMG, virtual disk or compressed stream reaches the parser cut.

- Detection is unchanged: the descriptor set.
- The descriptor set, the first sector of the root directory that supplies
  the names (the primary root, or the Joliet root when Joliet names are
  used) and the continuation area of the primary root's `SP`/`ER` entries
  must be present: without them whether Rock Ridge applies, or which
  hierarchy names the files, is unknown. Otherwise the image is the error
  it was before: `Truncated ISO 9660 volume: N blocks of B B need S B, P B
  present`.
- Extents are still checked against the declared volume ("lies outside the
  volume"); a defect in the bytes present is noted as for a complete image.
- A directory whose extent lies partly or wholly past the end of the file
  is read up to its last whole sector before the end (a record never
  crosses a sector, so none is cut) and counted:
  "N directories lie partly or wholly past the X present; their records
  past it were not read". So is a directory that a `CL` entry moved past
  the end.
- A record whose Rock Ridge entries continue past the end of the file is
  skipped, since its name and type are unknown: "N directory records carry
  Rock Ridge entries continued past the X present; they were not read".
- A regular file is listed only when all of its sections are present:
  "N regular files were not listed: file data lies partly or wholly past
  the X present".
- A path table, the El Torito boot catalog or a boot image past the end of
  the file is noted ("lies past the X present"); a boot image is listed
  only when all of it is present.
- A note states "Volume truncated: X of Y present; files are listed only
  when all of their data is present".

## Assumption register

| ID | Assumption | Falsification probe |
| --- | --- | --- |
| I1 | A primary volume descriptor whose both-byte-order fields agree identifies ISO 9660 strongly enough to make later damage a parse error | `primary_descriptor_damage_prevents_detection_or_is_a_parse_error`; every-prefix sweep of a synthetic image |
| I2 | Rock Ridge takes precedence over Joliet, as in Linux and libarchive | `rock_ridge_takes_precedence_over_joliet_and_ieee_identifiers_count`; bsdtar fixture with both |
| I3 | `RRIP_1991A` identifies Rock Ridge 1.09/1.10 | libarchive writes it (fixture `rockridge.iso.gz`); the RRIP 1.09 document itself was not obtained (not verified against it) |
| I4 | Platform ID 0 no-emulation images are x86 real-mode code | El Torito 4.3 and 5.3: the BIOS jumps to the loaded sectors; the code model only supplies extensions |
| I5 | Platform ID 0xEF images are EFI system partitions, sector count below 2 meaning the rest of the volume | Taken from libisofs (quoting UEFI 2.4 12.3.2.1) and EDK2 code; the UEFI text itself was not obtained (not verified) |
| I6 | A file whose data starts at a boot entry's load RBA is that boot image | `a_boot_image_file_gives_its_size_and_is_not_listed_as_a_member`; bsdtar and hdiutil fixtures name `/boot/boot.bin` |
| I7 | Trailing data after the volume is a hybrid image's appended partition only when the system area holds a partition table | `hybrid_system_areas_and_trailing_data` |
| I8 | Directory record byte-order disagreements are writer bugs, not a different layout | `byte_order_disagreement_in_records_uses_the_little_endian_half` |
| I9 | A truncated image is a prefix of the whole volume | `fixture_prefixes_are_truncated_volumes_that_list_only_members_inside_them` and the synthetic sweep check every member of each sampled prefix against the whole parse; not tested on a real cut disc image |

## Known boundaries

| Boundary | Behavior |
| --- | --- |
| Raw 2352-byte sector images (BIN/CUE, CD-ROM XA Mode 2) | Not recognized: the descriptor set is expected at 0x8000 |
| Multisession images (a later session's descriptor set) | Only the first session's set at 0x8000 is read; the data of later sessions is trailing data and an error unless the system area holds a partition table |
| High Sierra (`CDROM` at 0x8009) | Not recognized |
| UDF filesystems | Read by the [UDF family](udf.md), which reports a bridge disc when its UDF volume opens through the root directory; otherwise ISO 9660 reports the disc and notes the recognition sequence |
| Enhanced volume descriptors (ECMA-119 version 2) | Counted, not used for names |
| Interleaved files, associated files, Rock Ridge sparse files (`SF`), zisofs (`ZF`) | Not read; counted in notes |
| Rock Ridge symbolic links, devices, FIFOs, sockets | Not read; counted |
| Files on other volumes of a volume set | Not read |
| The system area's MBR boot code and the GPT or MBR partitions of hybrid images | Noted, not parsed or classified |
| Members nested deeper than the 4 KiB probe can recognize (for example an ISO 9660 image inside an ISO 9660 image, whose descriptor set is at 0x8000) | Not listed |
| Consoles whose disc header fills the system area (Saturn, Sega CD, Dreamcast) | Recognized by their console parsers first, as before |
| Section entry selection criteria and boot info tables | Not interpreted |
| Truncated volumes | Files whose sections are all present are listed, the rest counted; entries of directories past the end are not known, only those directories are counted |
